# UI専用操作一覧

この一覧は、管理画面にはあるが運営支援AIのMCPには公開していない操作を、管理者へ案内するための正本です。
AIはここにある操作を直接HTTP、DB、R2、ソース編集、Git、デプロイで代替してはいけません。

## 案内の共通手順

1. MCPで実行できない操作であることを明示する。
2. 管理者が開く画面名と、画面内の操作を案内する。
3. 変更の影響や確認事項を短く説明する。
4. 管理者が画面で変更した後、決め打ちせずMCPで最新状態を再取得する。
5. 必要なら同じ条件で割当案の作成・検証をやり直す。

「操作しました」「設定しました」と報告するのは、MCPの実行結果で確認できた操作だけにする。

## UI専用操作

### メンバーの有効化・利用停止

- MCP実行: できない。
- 到達先: 対象グループの「基本設定（グループ名）」→「メンバー」→「メンバー管理」。
- 案内: 対象メンバーの状態を「有効」または「利用停止」に変更する。
- 注意: 利用停止では基本設定や所属情報を残したまま、通常の一覧・母数・割当対象から除外される。既存の割当が消えるなどの影響があるため、予備要員を優先順位調整のためだけに停止しない。
- 変更後: メンバー一覧とシフト割当対象をMCPで再取得する。

### シフト・勤怠ルール

- MCP実行: できない。
- 到達先: 「基本設定（グループ名）」→「シフト・勤怠ルール」。
- 対象: 予定休憩の自動設定、予定休憩の確認、1日・週の実働上限、勤務間インターバル、連続勤務日数、休日数など。
- 案内: 変更候補の値、警告や割当結果への影響、店舗の就業ルール・契約上の確認事項を示す。
- 注意: AIが「ルールを緩める」と決め打ちしない。変更後は現在の設定を再取得し、割当案を同じ条件で再作成・再検証する。

### グループ招待の発行・取消

- MCP実行: できない。
- 到達先: 「基本設定（グループ名）」→「メンバーを招待」または招待管理。
- 案内: 招待URLの発行・取消を管理者が画面で行う。URLをチャットやレポートへ転載しない。
- 変更後: 招待対象が加入したか、または取消済みかをメンバー一覧で確認する。

### 運営支援AIの権限設定

- MCP実行: できない。
- 到達先: 「基本設定（グループ名）」→「運営支援AI関連」→AI権限設定。
- 案内: シフト作成、シフト公開、日次承認・差戻し、月次承認・差戻し、お知らせ配信などの許可を個別に変更する。
- 注意: キーの発行・失効と権限設定は別の操作。月次承認などを許可する場合は影響範囲を確認する。
- 変更後: APIキーの状態と利用可能なMCPツールを再取得する。

### 接続パック・運営支援APIキーの発行・失効・再発行

- MCP実行: できない。
- 到達先: 「基本設定（グループ名）」→「運営支援AI関連」→AI接続管理。
- 案内: キーを発行、失効、再発行し、接続パックを必要な管理者へ安全な経路で渡す。秘密値を会話、レポート、Gitへ出さない。
- 注意: 再発行後は古いキーを使わず、接続先とグループ範囲を確認してから接続を再設定する。

### グループ作成・削除

- MCP実行: できない。
- 到達先: 上部の「グループ作成」、削除は対象グループの「基本設定（グループ名）」の管理操作。
- 案内: グループ名などを入力して明示的に作成・削除する。削除はメンバー、シフト、勤務記録、お知らせ等への影響を確認する。
- 変更後: 作成後はグループ一覧と所属メンバーをMCPで再取得する。削除後は対象グループを再利用しない。

### サイト利用者・サイト管理者の管理

- MCP実行: できない。
- 到達先: 上部の「サイト管理」→サイト利用者管理。
- 案内: サイト利用者の有効化・利用停止、サイト管理者権限、グループ作成権限を画面で変更する。
- 注意: サイト管理者権限はグループ管理者権限とは別。対象メールアドレスと付与する権限を明示してから操作する。
- 変更後: 対象者が認証後に利用できる状態かを確認する。

### デモデータ初期化

- MCP実行: できない。
- 到達先: デモ環境の「サイト管理」→「デモデータの初期化」。
- 条件: デモ環境かつサイト管理者であること。
- 案内: 全データが初期シードへ戻ること、現在の検証データが失われることを説明し、管理者の明示確認を得る。
- 変更後: 初期化後のグループ、メンバー、シフト状態をMCPで再取得する。

## 割当時のUI案内

人員不足や労務注意をMCPだけで解消できない場合は、次の選択肢を根拠付きで提示する。

- 必要人数、営業時間、勤務枠を見直す。
- メンバーを追加する。
- 利用停止中の予備要員を、管理者が有効化してから候補に含める。
- 就業ルールを確認したうえで、管理者がシフト・勤怠ルールを画面で変更する。

予備要員の利用停止は割当優先順位を下げるための設定ではない。停止には既存割当の削除、本人用キーの失効、カレンダー購読解除などが伴い、再有効化しても元の状態は自動復元されない。通常メンバーだけの案を先に作成し、不足を報告したうえで、管理者了承後に予備要員を含む別案を作成する。
