# KINBANアシスタント運用ガイド

## 何を権限で決めるか

KINBANの「メンバー管理」から、グループごとに次の操作をオン／オフできます。

1. シフト作成（割当下書きを含む）
2. シフト公開
3. 勤怠承認／差戻し（日次）
4. 勤怠承認／差戻し（月次）
5. お知らせ配信

初期値は、月次の勤怠承認／差戻しだけオフです。

## メッセージを処理する流れ

1. AIは `claim_next_assistant_message` で未処理メッセージを1件取得します。
2. 送信者が代表管理者または管理者なら、返却される `contextMode` は `manager` です。
3. `manager` のときだけ、そのメッセージの依頼として、有効化済みの操作を実行できます。
4. メンバーからのメッセージは `member` です。本人への返信、保留、処理完了だけに使い、シフト公開や勤怠承認などの管理操作は行いません。

`contextToken` は短時間だけ有効で、取得したメッセージにだけ結びつきます。`.env.local`、Git、レポート、共有ログには保存しません。

## 確認トークンについて

手作業で確認トークンを発行・コピーする運用は廃止しました。MCP側で、管理者メッセージ由来のコンテキストとグループ権限の両方を検証します。

公開、勤怠の承認・差戻し、お知らせ配信を実行した場合は、対象と結果を `workspace/reports/` の作業報告に残します。アプリ側にも操作ログが自動記録されます。
