# 日次運営確認

## 目的

新着メッセージ、希望受付期限、未提出、当日のシフト、勤怠異常候補を確認し、変更を加えずに管理者向けの短いレポートを作成する。

## 前提

- `AGENTS.md` と対象のRunbookを先に読む。
- 対象グループIDは `.env` の `KINBAN_GROUP_ID` と一致するものだけを扱う。
- 詳細データを読む必要がある場合は、管理者がその回に発行した運営コンテキストを使う。コンテキストがなければ、取得できる範囲だけを確認して「運営コンテキスト待ち」と記録する。

## 手順

1. `list_groups` で対象グループとAIキーのスコープを確認する。
2. 運営コンテキストがある場合、`group_dashboard`、`list_shift_plans`、`get_work_records`、`get_assistant_message_queue_summary` を必要最小限の期間で呼ぶ。
   - 日次確認ではメッセージ本文や送信者を一覧取得しない。未処理件数だけを確認する。
   - 本文の処理が必要な場合は、このSkillを終え、`assistant-messages` Skillで1件ずつclaimする。
3. 次の3区分に整理する。
   - **確認のみで完了**: 異常なし、期限が近くない、未処理なし。
   - **管理者確認が必要**: シフト穴、希望未提出、未申告・未承認、差戻し候補、メンバーからの要判断メッセージ。
   - **情報不足**: コンテキスト不足、キー失効、対象期間不明、矛盾するデータ。
4. `workspace/reports/` に日付付きの短い要約を保存する。メールアドレス、本文、トークン、API応答全文は残さない。

## 出力例

```text
実施: 2026-07-20 09:00 JST
対象: サンプル店
結果: 要確認 2件
- 希望受付: 締切まで2日、未提出あり。催促文案の確認が必要。
- 勤怠: 前日分に未申告候補あり。日次承認前に確認が必要。
次の行動: 管理者へ確認依頼。変更操作は未実施。
```

## 成功条件

- 変更操作、送信、公開、承認をしていない。
- 要確認事項に対象・理由・期限がある。
- 異常がなければ「異常なし」と一行で残している。

## 失敗時

- 認証やコンテキストで失敗した場合、再試行を連打しない。
- 操作名、時刻、必要な管理者対応だけを記録する。
