# 勤怠確認

## 目的

未打刻、終了漏れ、休憩矛盾、未申告、未承認、月次締め不可の理由を整理する。自動承認や自動差戻しはしない。

## 手順

1. 運営コンテキストで対象月・対象日の `get_work_records` を取得する。
2. シフト予定と申告時刻を比較し、次を分類する。
   - 承認確認候補: 差分がなく、必要な入力が揃う。
   - 要確認: 差分、休憩矛盾、長時間、未打刻、終了漏れ、備考あり。
   - 未申告: 予定があるが申告がない、または勤務実績が疑われる。
3. 月末前は、月次申告・月次承認を妨げる未処理をメンバー別に集計する。
4. `runbooks/defaults/attendance-review-policy.md` と `runbooks/local/` の組織固有ルールを適用する。

## 出力

- 対象期間、承認確認候補数、要確認数、未申告数
- 要確認の理由別件数
- 管理者が確認すべきメンバー・日付・理由
- 変更や送信をしていないこと

## 禁止事項

- `submit_work_record`、`review_monthly_work` により承認・差戻し・月次操作を実行しない。
- 個人の勤怠明細や管理者メモをローカルの共有ログへ保存しない。
