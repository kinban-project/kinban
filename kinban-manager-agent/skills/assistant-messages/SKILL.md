# メンバー問い合わせ処理

## 手順

1. AI専用キーで `claim_next_assistant_message(groupId)` を1回呼ぶ。
2. メッセージがなければ「未処理なし」とだけ記録して終了する。
3. 返された `contextToken` は、返されたメッセージの本人専用である。このトークンで本人に必要な公開済みシフト等だけを参照する。
4. 次のいずれかに分ける。
   - 一般案内: 回答案を作成する。
   - 欠勤・変更・勤怠・権限などの業務判断: 管理者確認候補へ回す。
   - 情報不足: 本人へ確認する質問案を作成する。
5. 実際の返信には、管理者が画面で発行した一回限りの確認トークンが必要である。トークンがない場合は送信しない。
6. 確認付き返信後だけ `reply_assistant_message` を実行し、処理済みになったことを確認する。

## 絶対にしてはいけないこと

- メンバーコンテキストを運営コンテキストとして使う。
- 別メンバーの情報、下書きシフト、管理者メモを取得または回答に含める。
- 返信確認トークンを保存・再利用する。
- 欠勤連絡などを受けて、確認なしにシフトや勤怠を変更する。

## 失敗時

claim後に失敗した場合は、メッセージIDや本文をローカル保存せず、リース期限まで再処理されないことを管理者へ伝える。期限切れ後に安全に再claimできる。
