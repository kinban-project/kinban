# KINBAN 環境別デプロイ運用

## 方針

機能の正本は `main` に集約し、デモ／本番の違いはブランチではなく環境変数とデプロイ先の設定で切り替えます。環境ごとのデプロイ用ブランチは、同じ `main` の内容をどこへ反映するかを明示するために使います。

| ブランチ | 用途 | 主な設定 |
| --- | --- | --- |
| `main` | 共通の最新ソース・ローカル開発の基準 | 機密値は置かない |
| `develop` | ローカルでの確認用スナップショット | `DEMO_MODE` は必要に応じて設定 |
| `deploy/chatgpt-demo` | ChatGPT Site の公開デモ | `DEMO_MODE=true`、`NEXT_PUBLIC_DEMO_MODE=true`、デモ日時を利用 |
| `deploy/cloudflare-prod` | Cloudflare の非デモ環境 | `DEMO_MODE=false`、Google／Resendを設定、運営支援AIは未接続 |

## 環境を更新する手順

機能変更を公開先へ反映するときは、次の順に行います。

```powershell
git switch main
git pull github main
git status

# 対象環境のブランチを main の最新へ追従させる
git switch deploy/chatgpt-demo
git merge --ff-only main
git push github deploy/chatgpt-demo

git switch deploy/cloudflare-prod
git merge --ff-only main
git push github deploy/cloudflare-prod
```

ChatGPT Site は `deploy/chatgpt-demo`、Cloudflare は `deploy/cloudflare-prod` をデプロイ元に設定します。設定画面でブランチを指定できない場合は、`main` から対象環境へ保存版を作成する運用にし、環境変数だけは各ホスティング側で管理します。

## ChatGPT Site の環境値

公開デモでは、ホスティング側の環境変数に次を設定します。

```text
DEMO_MODE=true
NEXT_PUBLIC_DEMO_MODE=true
PUBLIC_APP_URL=https://<公開デモURL>
```

デモ日時はアプリのデモ時計を使います。機密値やローカル用のGoogle／Resend設定はデモ環境へ持ち込みません。

## Cloudflare 本番の環境値

Cloudflare 側の Production 環境に設定します。値はリポジトリへコミットしません。

```text
DEMO_MODE=false
NEXT_PUBLIC_DEMO_MODE=false
PUBLIC_APP_URL=https://kinban-prod.kinban.workers.dev
GOOGLE_REDIRECT_URI=https://kinban-prod.kinban.workers.dev/auth/google/callback
INITIAL_OWNER_EMAIL=<サイト管理者のメールアドレス>
GOOGLE_CLIENT_ID=<Google OAuthクライアントID>
GOOGLE_CLIENT_SECRET=<Google OAuthクライアントシークレット>
RESEND_API_KEY=<Resend APIキー>
RESEND_FROM_EMAIL=KINBAN通知 <notification@send.kinban.jp>
RESEND_REPLY_TO=info@kinban.jp
```

運営支援AIを接続しない間は `KINBAN_AGENT_RUNTIME_URL` を設定しません。Google Cloud Console の承認済みリダイレクトURIにも、上記の本番URLを登録します。

## Cloudflare の変数を保持する設定

`wrangler.production.jsonc` の `keep_vars: true` により、Wranglerデプロイ時にCloudflareダッシュボードで設定した環境変数を設定ファイルの空値で上書きしないようにします。シークレットの値は引き続きCloudflare側で管理し、ログやGitへ出力しません。

## デプロイ後の確認

1. 公開URLが表示され、カレンダー読込中のままになっていないこと。
2. Googleログインの開始URLが開き、コールバックURLが一致すること。
3. サイト管理者の初回状態と招待URLのベースが本番URLになっていること。
4. デモ環境だけがユーザー切替・デモ日時を表示すること。
5. CloudflareのD1／R2バインディングと、必要なマイグレーションの適用結果を確認すること。
