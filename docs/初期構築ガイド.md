# KINBAN 初期構築ガイド

GitHubから取得したKINBANを、まずローカルで安全に動かすための手順です。公開デモや本番環境への反映は、この手順とは分けて管理します。

## 1. 前提

- Windows PowerShell、Git、Node.js 22.13 以上、npmを用意します。
- Cloudflare D1へ接続する場合は、CloudflareアカウントとWranglerの認証が別途必要です。
- 秘密値（APIキー、OAuthシークレット、初期セットアップシークレット）はGitに保存しません。

```powershell
git clone https://github.com/take365/kinban.git
Set-Location .\kinban
node --version
npm --version
```

## 2. 自動構築

通常は、既存の`.env.local`を上書きせず、依存関係をそろえて開発サーバーを起動できます。

```powershell
.\scripts\bootstrap-kinban.ps1 -Start
```

ローカルD1をサンプルデータで再投入する場合だけ、既存データが消えることを確認して明示します。

```powershell
.\scripts\bootstrap-kinban.ps1 -SeedLocal
# 自動実行する場合（ローカルDBだけ）
.\scripts\bootstrap-kinban.ps1 -SeedLocal -Yes -Start
```

`-SeedLocal`を指定しない限り、DBは変更しません。公開環境のDBリセットやデプロイはこのスクリプトの対象外です。

## 3. 環境変数

初回は`.env.example`から`.env.local`が作られます。最低限、ローカル確認ではデフォルト値のまま起動できます。

本番・認証付き環境では、次を環境に合わせて設定します。

| 目的 | 主な変数 |
| --- | --- |
| デモ | `DEMO_MODE`, `NEXT_PUBLIC_DEMO_MODE`, `DEMO_DEFAULT_USER_ID` |
| 初回サイト管理者 | `INITIAL_OWNER_EMAIL`, `INITIAL_SETUP_SECRET` |
| Googleログイン | `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI` |
| メール招待 | `RESEND_API_KEY`, `RESEND_FROM_EMAIL`, `RESEND_REPLY_TO` |
| Web Push | `VAPID_SUBJECT`, `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` |
| 公開URL | `PUBLIC_APP_URL` |

OAuthのリダイレクトURL、Resendの送信ドメイン、CloudflareのSecret設定は、配置先ごとに登録します。値そのものはIssue、チャット、Gitへ貼り付けません。

## 4. 起動と確認

```powershell
npm run dev -- --port 3003
```

別のPowerShellで、ホーム画面だけを確認します。

```powershell
.\scripts\verify-setup.ps1 -SkipMcp
```

運営支援AIの接続確認を行う場合は、`kinban-manager-agent\.env.local`に、対象グループ専用のMCP URL・キー・グループIDを設定してから、次を実行します。

```powershell
..\kinban-manager-agent\scripts\verify-connection.ps1
```

この確認は`list_groups`の読み取りだけを行い、シフト・勤怠・お知らせを変更しません。

## 5. 運営支援AIの準備

1. グループ管理者がKINBANのメンバー管理から「運営支援AIキー」を発行します。
2. キー発行画面の接続パック、またはテンプレートの`kinban-manager-agent`を作業用フォルダへコピーします。自動展開する場合は次を使えます。

```powershell
.\scripts\setup-manager-agent.ps1 -Destination ..\kinban-manager-agent-local
```

既存の作業用フォルダをテンプレートで更新する場合だけ`-Update`を付けます。`.env.local`、`workspace`、ローカルrunbookはテンプレート側のスクリプトが保護します。
3. `.env.example`を`.env.local`へコピーし、次を設定します。
   - `KINBAN_MCP_URL`
   - `KINBAN_ASSISTANT_API_KEY`
   - `KINBAN_GROUP_ID`
   - `KINBAN_TIMEZONE=Asia/Tokyo`
4. `kinban-manager-agent\scripts\verify-connection.ps1`で読み取り確認をします。
5. `AGENTS.md`、`skills/`、`runbooks/`を読ませてから、最初のタスクを開始します。

運営支援AIは、最初に対象グループ・対象期間・現在状態を読み取り、変更案を示してから書き込みます。公開、勤怠承認、差戻し、全体通知などは人間の確認を挟む運用にします。

## 6. 初期サイト管理者

本番環境では、`INITIAL_OWNER_EMAIL`と`INITIAL_SETUP_SECRET`をCloudflare Secretなどへ設定し、ChatGPTで本人確認した同じメールアドレスの利用者が初回セットアップを実行します。

- `INITIAL_SETUP_SECRET`は推測しにくい一時値にします。
- 初回セットアップ完了後は、Secretを削除またはローテーションします。
- `INITIAL_OWNER_EMAIL`は公開リポジトリやドキュメントへ書きません。
- ローカルの簡易ユーザー切替（デモモード）を本番で有効にしません。

## 7. 失敗時の切り分け

| 症状 | 確認 |
| --- | --- |
| Node.jsエラー | `node --version`が22.13以上か、依存関係を再インストール |
| ホームが開かない | ポート使用状況、開発サーバーログ、`.env.local`の構文 |
| DBが空 | ローカルだけ`npm run db:seed:local`を明示実行 |
| 401/403 | ChatGPTログイン、サイト利用者状態、グループ所属、キーの対象グループ |
| MCP接続失敗 | MCP URL、Bearerキー、グループID、ネットワークを再確認 |
| 文字化け | MCPリクエストをUTF-8 JSONで送信し、再取得して保存結果を確認 |

エラーを直すために、秘密値をログへ出力したり、未知のグループIDや別のキーを推測して再試行したりしません。
