# KINBAN 検証基盤

## テスト層

| 層 | 目的 | 例 |
| --- | --- | --- |
| 契約テスト | route、MCP、権限、競合、不変条件の静的確認 | `tests/*contract.test.mjs` |
| ビルド | TypeScript/RSC/routeの構築確認 | `npm run build` |
| DB検証 | migration・seed・再実行性 | Wrangler local D1 |
| ブラウザQA | PC・スマホの実操作と表示崩れ | Browser / Chrome |
| 業務受入 | 希望、割当、公開、打刻、承認、差戻し | `qa/` のシナリオ |
| 境界検証 | 多人数、複数枠、ページング、SQL変数上限 | 5グループ・100人規模 |

## 標準コマンド

```powershell
npm test
npm run lint
npm run db:generate
```

`npm test`はビルドと軽量な描画・契約テストを確認するが、業務受入テストや実機Push、実際のMCPキー接続を代替しない。秘密キーを使うテストはローカル環境へ限定し、値を出力しない。

## 重要シナリオ

- 同日の複数枠を勤務申告へ集約し、予定実働・予定休憩・日次承認を一致させる。
- 公開済みシフトを変更した場合、差分・不足・監査ログを確認する。
- 本人用キーで他人のグループ・勤務記録・メモを取得できない。
- 運営支援AIがclaim競合、再試行、途中停止後に二重処理しない。
- 100件超のページングとフィルタ条件の適用順を確認する。
- Node.js 22.12.9を拒否し、22.13.0以上を許可する。

## 実施記録

実施日時、環境、seed、対象グループ、実行コマンド、結果、未実施項目を `qa/` またはIssueへ記録する。計画書だけを実行証跡として扱わない。
