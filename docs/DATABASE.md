# KINBAN データベース運用

## 正本

- スキーマ: `db/schema.ts`
- 変更履歴: `drizzle/*.sql` と `drizzle/meta/`
- ローカルseed: `scripts/seed-local.sql`
- 接続: `db/index.ts`、`wrangler.jsonc`

この文書に全カラムを複製しません。新しいテーブルや制約を追加したら、schemaとmigrationを同じ変更で更新し、用途・所有グループ・削除影響をこの文書またはドメインモデルへ追記します。

## 変更手順

1. `db/schema.ts`を変更する。
2. `npm run db:generate`でmigrationを生成し、SQLをレビューする。
3. ローカルD1でmigration・seed・主要APIを確認する。
4. 既存データに対するNULL、既定値、再実行性、ロールバック方針を確認する。
5. 本番・公開デモへは、対象環境を明示してから適用する。

## データ削除の境界

- ローカルD1: `npm run db:seed:local` によりリセット可能。実行前にローカルであることを確認する。
- 公開デモ: デモ用データとしてリセット可能だが、利用中の確認がないか確認する。
- 本番D1: seedや全削除を実行しない。必要時はバックアップ、対象限定migration、復旧手順を先に用意する。
- R2: D1の参照行を先に確認し、孤立ファイルと公開URLの扱いを決めてから削除する。

## バックアップ

運営権限内のJSON exportは確認・移行用であり、D1の完全バックアップの代替ではありません。少なくとも本番では、D1バックアップ、R2オブジェクト、migration履歴、環境変数名（値は除外）を別経路で管理します。
