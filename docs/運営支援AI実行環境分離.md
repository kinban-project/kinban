# 運営支援AI・メンバー支援AIの実行環境分離

## 目的

KINBANのMCP権限と、AIが動作する実行環境の権限を分けます。グループ専用キーで操作範囲を制限していても、AIを開発用PCや開発用ユーザーと同居させると、ソース、Git、ローカルDB、環境変数へ到達できるためです。

## 推奨構成

- 開発・運用AI（Dev/Ops）は、ソースコード、Git、デプロイ、開発用DBを扱う別の役割にする。
- 運営支援AI・メンバー支援AIは、ChatGPT WorkのクラウドProjectなど、開発環境から分離された実行場所で使う。
- Work用Projectへ渡すのは、業務ガイド、運用スキル、必要なMCP接続情報だけにする。
- アプリ本体のリポジトリ、`.env.local`、Git資格情報、開発用MCP、ローカルDBのファイルは渡さない。
- KINBANへは、クラウドから到達できる本番・検証用MCP URLを使う。`localhost` のMCPはクラウドから到達できない。

接続セットをフォルダへコピーしただけでは隔離になりません。フォルダが別でも、同じPC・ユーザー権限で実行すれば開発環境へ到達できる可能性があります。

## 運営支援AIの境界

運営支援AIは、MCPで許可されたグループ内の業務だけを扱います。

- MCP以外のHTTP直接呼出しをしない。
- ローカルDBやR2を直接読まない、変更しない。
- ソースコード、Git、デプロイ設定、環境変数を編集しない。
- MCPで不足する操作をコード修正で補わず、管理者または開発・運用AIへ報告する。
- 公開、承認、差戻し、全体通知などは、明示された業務フローとグループ権限を確認してから実行する。
- 書き込み前に対象・状態・version・必要な確認値を読み、保存後に結果を再取得する。

## ローカル利用

ローカル実行は開発・検証用の次善策です。専用フォルダ、専用ユーザー、限定したファイル権限、検証用のキーとDBを使います。ただし、同じPC上で開発用プロジェクトと同居する場合は、クラウド運用と同じ安全性にはなりません。
