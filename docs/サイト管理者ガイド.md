# KINBAN サイト管理者ガイド

対象読者は、サイト全体の利用者、招待、サイト管理者権限、グループ作成権限を管理するサイト管理者です。グループ内のシフト運用は[管理者ガイド](管理者ガイド.md)を参照します。

## 利用者を招待する

1. **サイト管理**を開く。
2. 招待先メールアドレスを入力し、招待URLを発行する。
3. 有効期限と状態を確認し、URLを安全な経路で本人へ渡す。
4. 本人の初回ログイン・有効化を確認する。

招待URLは発行直後の表示やメール本文など、許可された経路だけで扱います。URLをGit、ドキュメント、公開チャットへ貼りません。

## 利用者の状態と権限

- **有効**: サイトへログインできる。
- **利用停止**: アカウント情報を残したまま、通常利用から除外する。
- **サイト管理者**: サイト利用者、招待、サイト管理者権限、グループ作成権限を管理する。
- **グループ作成**: 新しいグループを作成できる。作成後のグループ運用権限とは別に考える。

権限を変更する前に対象メールアドレスを確認します。最後のサイト管理者や復旧用アカウントを停止しないようにします。人の役割を変更しても、グループ内の代表管理者・管理者・メンバー権限とは別の管理単位です。

## 認証方式

Googleログイン、メール招待リンクなど、実際に有効な認証方式と環境設定を確認します。ローカル、公開デモ、本番で認証先・DB・通知先を混ぜません。認証エラーは、まず環境変数、許可済みリダイレクトURI、サイト利用者の状態、現在の環境を順に確認します。

## 復旧と切り分け

- サイト管理者へ入れない場合は、開発・運用担当へ対象環境、ログインメール、発生時刻、直前の変更を伝える。
- 認証設定やDBを直接変更する場合は、先にバックアップと復旧手順を確認する。
- 本番の利用者・DB・R2を、公開デモやローカルのseedでリセットしない。
- APIキーや招待URLは再発行・無効化を優先し、値をログやIssueへ記録しない。

技術的な復旧条件は `docs/ARCHITECTURE.md`、`docs/DATABASE.md`、`docs/AUTHORIZATION.md`、運用手順は `OPERATIONS.md` を参照します。
